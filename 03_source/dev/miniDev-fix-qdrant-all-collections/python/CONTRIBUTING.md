## 📜 Кодекс поведения

Мы придерживаемся принципов уважительного и профессионального взаимодействия:

- ✅ Будьте вежливыми и уважительными

## 🎯 Как внеступить в разработку

### 1. Сообщения об ошибках (Bug Reports)
Если вы нашли ошибку, создайте Issue со следующей информацией:
- Четкое описание проблемы
- Шаги для воспроизведения
- Ожидаемое и фактическое поведение
- Версия Python и qdrant-client
- Логи/скриншоты (если применимо)

### 2. Предложения улучшений (Feature Requests)
Для новых функций опишите:
- Четкую формулировку проблемы
- Предлагаемое решение
- Альтернативные варианты
- Дополнительный контекст

### 3. Исправления (Fixes)
- Начните с обсуждения в Issue
- Убедитесь, что исправление решает конкретную проблему
- Добавьте тесты для нового функционала

## 💻 Руководство по коду

### Стиль кода
- Используйте **Python 3.7+** совместимость
- Следуйте **PEP 8** (используйте black для форматирования)
- Максимальная длина строки: **88 символов**
- Используйте **typing hints** для всех функций
- Документируйте все публичные функции и классы

### Примеры кода
```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Описание модуля или функции
"""

from typing import Dict, List, Any, Optional


def example_function(param: str, optional_param: Optional[int] = None) -> Dict[str, Any]:
    """
    Краткое описание функции.
    
    Args:
        param: Описание параметра
        optional_param: Описание опционального параметра
        
    Returns:
        Описание возвращаемого значения
        
    Raises:
        ValueError: Когда param пустой
    """
    if not param:
        raise ValueError("param не может быть пустым")
    
    return {"result": f"Обработан: {param}"}
```

### Именование
- **Функции и переменные**: `snake_case`
- **Классы**: `PascalCase`
- **Константы**: `UPPER_SNAKE_CASE`
- **Приватные методы**: `_leading_underscore`

### Обработка ошибок
```python
try:
    result = risky_operation()
except SpecificError as e:
    logger.error(f"Описание ошибки: {e}")
    raise CustomException("Пользовательское сообщение") from e
except Exception as e:
    logger.exception("Неожиданная ошибка")
    raise
```

## 🧪 Тестирование

### Перед отправкой изменений
1. **Проверка синтаксиса**:
   ```bash
   python -m py_compile qdrant_fixer.py qdrant_status.py
   ```

2. **Тестирование импортов**:
   ```bash
   python test_imports.py
   ```

3. **Ручное тестирование**:
   ```bash
   python qdrant_fixer.py --dry-run
   python qdrant_status.py --quiet
   ```

### Тестовые сценарии
- Тестируйте с разными конфигурациями
- Проверяйте обработку ошибок
- Тестируйте на разных версиях Python (3.7, 3.8, 3.9+)
- Используйте `--dry-run` для безопасного тестирования

## 🔄 Отправка Pull Request

### 1. Подготовка
1. **Fork** репозитория
2. **Клонируйте** свой fork
3. **Создайте** ветку для изменений:
   ```bash
   git checkout -b feature/описание-изменения
   ```

### 2. Внесение изменений
1. Внесите изменения в код
2. Обновите документацию
3. Добавьте тесты
4. Проверьте работоспособность

### 3. Описание PR
- **Заголовок**: Краткое описание изменений
- **Описание**: 
  - Что изменено и почему
  - Как тестировалось
  - Скриншоты (если применимо)
  - Связанные Issues

### 4. Чек-лист перед отправкой
- [ ] Код следует стилю проекта
- [ ] Добавлены/обновлены тесты
- [ ] Документация обновлена
- [ ] Все тесты проходят
- [ ] Описаны изменения в PR
